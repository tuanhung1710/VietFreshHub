# VietFresh Hub instructions

For code changes, follow `docs/CODING_STANDARDS.md`.

Before changing a feature, inspect the relevant source code and check the
applicable configuration, database schema, and confirmed requirements.
Do not treat items marked as proposals or unconfirmed decisions as approved.
If the standards conflict with the current project or the task request,
point out the conflict and do not silently change the stack or database schema.

After making changes, run the relevant tests or build and report the exact
commands and results.

## Mandatory approval before editing

- Do not create, edit, delete, rename, move, overwrite, or format any project file without my explicit approval.
- A request to explain, review, diagnose, suggest, or investigate is not permission to edit.
- Even when I request a code change, first inspect the relevant files and present the proposed changes and affected files. Do not apply the changes yet.
- Wait for my approval of that specific proposal before editing. Approval for one proposal does not authorize additional or unrelated changes.
- Until approval, use read-only actions only. Do not run formatters, code generators, migrations, or commands that modify project files or data.
- After approval, change only the approved files and scope. If more changes are needed, stop and ask me first.
